# FORMA WEB

Небольшой адаптивный сайт веб-студии на **четыре страницы**: главная, услуги, процесс разработки, контакты. Без базы данных, Docker, WordPress и дополнительных API. В комплекте установщик HTTPS-сайта для использования с **3x-ui + Xray REALITY**.

Скрипт рассчитан на людей, которым неудобно вручную настраивать Nginx и Certbot. Всё, что требуется ввести при установке, — **собственный домен и email**, а также при желании разрешить показ email на странице контактов.

## Что нужно до запуска

- VPS с **Ubuntu 22.04/24.04** или **Debian 12/13**, SSH-доступ с `sudo`/`root`.
- Собственный домен или поддомен и **A-запись DNS** на публичный IPv4 этого VPS. Если используется Cloudflare, установите *DNS only* (серое облако), без проксирования. Не создавайте неправильную AAAA-запись.
- Для Let's Encrypt нужен внешний доступ к **TCP/80**. Установщик предложит разрешить только этот порт в активном **UFW/firewalld**; если firewall находится в панели хостинга, порт 80 необходимо разрешить там. **TCP/443** остаётся за Xray, внутренний HTTPS-порт наружу открывать не нужно.
- Установщик самостоятельно выберет свободный внутренний HTTPS-порт из **8443, 9443, 10443, 11443, 18443**. Если `80` занят не Nginx, установщик безопасно остановится. Нестандартный порт веб-панели 3x-ui (например, 2053 или 8443) не меняется.
- Для установки используется обычный 3x-ui или 3x-ui в Docker с `network_mode: host`. При Docker bridge-режиме `127.0.0.1:8443` внутри контейнера **не указывает на Nginx хоста** — потребуется отдельная настройка сети контейнера.

## Установка: одна команда

```bash
curl -fsSL https://raw.githubusercontent.com/respectr38-wq/forma-web/main/bootstrap.sh -o /tmp/forma-bootstrap.sh && sudo bash /tmp/forma-bootstrap.sh respectr38-wq/forma-web
```
**Почему без конвейера `curl | bash`:** при запуске интерактивных вопросов внутри SSH/sudo на некоторых серверах дочерний Bash получает сигнал остановки (`T+` в `ps`). Загрузка скрипта в файл и отдельный запуск сохраняют обычный ввод терминала. При попытке интерактивного запуска через конвейер загрузчик теперь выводит подсказку вместо зависания.\n\nЕсли вы вошли на сервер **сразу как root** и команда `sudo` отсутствует, замените `sudo bash` в строке установки на `bash`.

Если на VPS нет `curl`, сначала выполните:

```bash
sudo apt-get update && sudo apt-get install -y curl
```

В установщике появятся вопросы (при активном UFW/firewalld также запрос на разрешение TCP/80):

```text
Домен сайта (например, site.example.com): studio.mydomain.ru
Email для уведомлений Let's Encrypt: admin@mydomain.ru
Показывать этот email на сайте для связи? [д/Н]: н
```

Если DNS ещё не настроен, скрипт остановится и подскажет, какую **A-запись** создать. Можно повторить установку после обновления DNS.

**Безопасность:** вы запускаете скрипт из GitHub с правами root. Перед использованием убедитесь, что доверяете владельцу репозитория, или скачайте и изучите исходный код. Не вводите в скрипт пароли, токены GitHub и ключи REALITY.

## Что установщик делает сам

1. Проверяет Ubuntu/Debian, домен, IPv4, занятые порты и наличие активного UFW/firewalld.
2. Устанавливает `nginx`, `certbot` и зависимости.
3. Размещает сайт в `/var/www/forma-selfsteal/ВАШ-ДОМЕН/`.
4. Настраивает HTTP на порту `80` для ACME-проверки.
5. Получает бесплатный сертификат Let's Encrypt.
6. Включает **HTTPS (TLS 1.3 / HTTP/2) только на `127.0.0.1:ВЫБРАННЫЙ_ПОРТ`**. Свободный порт выбирается автоматически.
7. Включает автопродление SSL через штатный `certbot.timer` либо создаёт резервный systemd timer, если штатного нет. Добавляет `deploy-hook`, который **после успешного продления плавно перезагружает Nginx** (`reload`, не `restart`).
8. Выполняет тест `certbot renew --cert-name ДОМЕН --dry-run`; если он не прошёл, выдаёт предупреждение с командой повторной проверки.
9. Печатает поля, которые нужно вписать в 3x-ui.

**Не меняет** Xray, существующие inbound, UUID, ключи REALITY, порт панели 3x-ui, SSH и существующие сайты. При согласии пользователя может **добавить только разрешение TCP/80** в активном UFW/firewalld. Не включает отключённый firewall и не открывает внутренний HTTPS-порт.

## Автоматическое продление SSL (включается установщиком)

Отдельно добавлять `crontab` не нужно. Установщик включает существующий `certbot.timer` и, **только если его нет или не удаётся запустить**, создаёт резервный таймер `forma-selfsteal-certbot-renew.timer`. Продление проверяется по расписанию; Certbot обновляет сертификат **только при приближении срока окончания**. После успешного обновления вызывается обработчик, выполняющий `nginx -t` и `systemctl reload nginx`. Xray, 3x-ui и SSH при этом не перезапускаются.

Проверить на VPS:

```bash
systemctl list-timers --all | grep -E 'certbot|forma-selfsteal'
sudo certbot renew --cert-name ВАШ-ДОМЕН --dry-run
sudo bash check.sh ВАШ-ДОМЕН
```

**Важно:** для продления по HTTP-01 домен всё время должен указывать на VPS, а порт **80/tcp** оставаться доступным извне. SSL-сертификат **самой панели 3x-ui**, если он получен другим инструментом, может иметь *отдельный* механизм продления: эта установка его не изменяет.

## Последний шаг: настройка 3x-ui

После надписи `ГОТОВО` откройте **3x-ui → Inbounds → свой VLESS + REALITY → Edit** и задайте:

| Настройка | Значение |
| --- | --- |
| Target / Dest | **Адрес `127.0.0.1:ПОРТ`, который выдаст установщик** (например, `127.0.0.1:8443`) |
| SNI / Server Names | **домен, который ввели при установке** |
| Xver | `0` |
| VPN port | Оставить `443` |
| Security | Оставить `REALITY` |
| Flow при TCP/RAW | Оставить `xtls-rprx-vision` |

**Не генерируйте заново** ключи REALITY, UUID или Short ID для уже работающего inbound. Обновите SNI в приложениях-клиентах (через обновлённую подписку или повторный импорт) и перезапустите **Xray**, а не весь сервер. Не ставьте `127.0.0.1:ПОРТ` в поле адреса VPN-клиента: это **локальная цель на сервере**.

Откройте `https://ВАШ-ДОМЕН` в браузере — сайт должен открыться без ошибок сертификата. Если VPN не подключается, сначала верните старые SNI и Target по сохранённой копии настроек 3x-ui.

## Установка из скачанного ZIP (без GitHub)

Распакуйте проект на сервере. В каталоге с файлами:

```bash
sudo bash install.sh
```

Для автоматизированного запуска без вопросов:

```bash
sudo bash install.sh --domain studio.example.com --email admin@example.com
```

Дополнительные параметры: `--target-port 9443` — вручную выбрать внутренний HTTPS-порт, `--firewall allow` — разрешить TCP/80 в активном UFW/firewalld без вопроса, `--firewall skip` — не менять firewall. Значения `example.com` — только пример: замените на настоящий домен и email. Показать публичный email можно через `--contact-email contact@example.com`.

## Проверка сайта после установки

Если файлы проекта есть на VPS:

```bash
sudo bash check.sh studio.example.com
```

Или вручную, заменив домен:

```bash
curl --fail --http2 --tlsv1.3 --resolve studio.example.com:8443:127.0.0.1 https://studio.example.com:8443/
# Замените 8443 на порт, показанный установщиком.
```

Внутренний HTTPS-порт (`8443`, `9443` и т. д.) **не должен быть доступен из интернета**. Не открывайте его в UFW/панели хостинга.

## Ограничения

- DNS-запись у регистратора нужно создать самостоятельно. Установщик не запрашивает доступ к аккаунту регистратора.
- Внешний firewall хостинг-провайдера и произвольные правила nftables/iptables автоматически не меняются. В таком случае TCP/80 потребуется разрешить самостоятельно. Скрипт не изменяет SSH, порт панели или 443 у Xray.
- Чтобы сертификат автоматически продлевался по HTTP-01, входящий TCP/80 должен оставаться доступным. Не закрывайте его сразу после установки без смены способа проверки домена.
- Действующий REALITY-инбаунд остаётся нетронутым — последнее изменение в 3x-ui выполняет пользователь.
- Не запускайте установщик повторно поверх уже установленного сайта для того же домена. Он специально защищён от перезаписи.
- Если сервер уже использует порт 80 не через Nginx, скрипт остановится. Если 8443 занят, автоматически выберет другой свободный внутренний порт. Никакие службы ради установки не отключаются.
- Если домен имеет AAAA-запись, проверьте, что IPv6 и порт 80 на нём работают. Для простой установки достаточно корректной A-записи и отсутствия AAAA.
- Продление другого сертификата **панели 3x-ui** через `certbot --standalone` может конфликтовать с Nginx на порту 80. Настройте для панели отдельный совместимый способ продления.
- Скрипт проверяет локальный HTTPS; доступность VPN и маскировку необходимо проверить отдельно после настройки inbound.
